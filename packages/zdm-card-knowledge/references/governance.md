# 卡片知识治理规则

- 一个编号代表一种卡片类型；状态和内容开关归档在编号下面，不另造编号。
- 设计编号与研发编号严格一一对应。
- 除明确废弃或置灰外，默认按使用中保留。
- 实验、历史、A/B 分流字段保留；没有批准信息时保持空值。
- 默认跨端共用编号与规范；不一致时记录例外并交由设计确认。
- 长期无人确认的记录继续保留，不自动删除或废弃。

## 证据等级

- `human-reviewed`：设计或研发已经明确确认并留有记录。
- `figma-traceable`：Figma 中存在组件实例、完整卡片节点或可回溯来源；是强证据，但不等于人工确认。
- `inferred`：由普通 Frame 名称、编号或视觉相似推测，必须复核。
- `unknown`：缺少足够信息。

## 冲突处理

- 设计负责人确认卡片定义、视觉规范和设计稿应有状态。
- 负责该页面的研发确认线上或代码中的实际实现。
- 若冲突影响交互、字段或业务条件，由产品参与决策。
- 第一期只覆盖设计稿，因此卡片库和设计负责人确认的设计定义是当前权威版本；研发不一致记为“实现待对齐”，不覆盖设计档案。

## 版本

使用 `YYYY.MM.DD-rN`，例如 `2026.09.01-r1`。同日每次管理员重新发布递增 `rN`；重大结构升级再增加单独的 schema 版本。
