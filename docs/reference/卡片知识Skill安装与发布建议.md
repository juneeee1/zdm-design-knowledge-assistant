# 卡片知识 Skill 安装与发布建议

## 结论

可以做到类似 Ant Design 的团队一键安装体验，但第一步不是先做复杂平台，而是把 `skills/zdm-card-knowledge/` 作为唯一可安装包维护好。

当前产物已经具备标准 Skill 目录、AI 操作说明、治理规则、查询脚本和完整知识快照。等团队确定代码托管位置后，把这个目录发布到内部 Git 仓库，再由团队统一安装入口或 Skill 安装器拉取即可。

## 推荐的三阶段方式

1. **现在：项目内验证**
   - 管理员更新 Figma 扫描资料。
   - 重新生成网页、Markdown 档案和 Skill 快照。
   - 设计负责人抽查卡片与状态。

2. **团队试用：内部仓库分发**
   - 把 `zdm-card-knowledge` 放入内部 Git 仓库。
   - 为产品、设计、研发、测试提供同一个安装入口。
   - 每次发布展示知识版本和变更摘要。

3. **成熟后：插件化入口**
   - 若还需要 Figma、飞书机器人、权限和自动同步，可封装为 Codex 插件或团队工作台。
   - Skill 仍负责 AI 的判断边界；网页负责可视化查找；飞书负责提醒与确认，不让三者重复保存权威资料。

## 发布流程

1. 管理员更新卡片源数据和人工复核结果。
2. 执行知识档案、网页数据和 Skill 快照生成。
3. 运行数据校验、Skill 校验与浏览器回归测试。
4. 将版本从 `YYYY.MM.DD-rN` 更新为新的发布号。
5. 发布静态网页，并把 Skill 同步到内部仓库。
6. 飞书机器人向设计群发送“新增、变更、废弃、待确认”的摘要与网页链接。

## 为什么暂不先做 Figma 插件

Figma 插件适合在设计师创建或修改卡片时提交变更，但无法替代产品、研发、测试需要的跨页面搜索和浏览。第一期用网页作为所有角色的入口、飞书作为提醒入口，成本最低且覆盖面最大。等提交流程稳定后，再让 Figma 插件承担“创建卡片/发起变更”的入口。
