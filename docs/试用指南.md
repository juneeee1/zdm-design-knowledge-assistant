# 试用与维护

## 团队使用

打开 [查询页面](../site/index.html)。按编号或关键词搜索，查看来源、状态与问题；卡片详情同时提供预览、原始备注、变体及页面关系，支持两卡比较。汇报页可通过浏览器打印为 PDF。网页是本地生成的文件，未部署外网。

当前页面中的知识与卡片原始证据分别标明版本。页面本身的视觉样式是工具界面，不是值得买官方视觉规范。

## AI 使用

先读 llms.txt，再按问题检索：

```bash
npm run query -- search 字号
npm run query -- get F01
npm run query -- search 20040
npm run query -- issues P0
npm run query -- health
node packages/zdm-card-knowledge/scripts/query-card.mjs compare 20040 20041
node packages/zdm-card-knowledge/scripts/query-card.mjs usages 20040
```

检索采用文本匹配，多关键词以空格分隔并同时满足；没有语义向量库，也没有联网聊天服务。搜索命中不代表选型已确认。没有命中时返回缺证据，不能自行创造规则。

## 更新一条知识

1. 在 knowledge 对应档案补事实和来源，保留状态、责任人和日期。
2. 新来源先登记 governance/sources.json；需要复核的问题记入 governance/issues.json。
3. 获得人工确认后填真实 reviewed_by 与确认记录，不能仅改状态标签。
4. 更新版本与 CHANGELOG，运行构建、校验和测试。
5. 检查生成页面，然后共享整个项目或按团队允许的方式发布。

```bash
npm ci
npm run build
npm run validate
npm test
```

首次克隆运行 npm ci。现有 site/index.html 无需安装依赖即可打开，但必须保留相对目录中的卡片图片与源文件。不能只发一个 HTML 后宣称图片和原始文档仍完整。

## 源项目同步

source/card-finder 不手工编辑。修正其源项目后执行 npm run sync:cards，再重新构建、校验。精炼档案中的历史版本引用需要人工核对，不应自动视为新快照已确认。同步不会自动关闭业务问题。

## 数据与产物

knowledge Markdown 和来源/问题 JSON 为编辑入口；site/index.html、site/knowledge-index.json、docs/本版验收数据.md 为生成产物。查询页面不提供伪审批按钮，状态变更须在源档案留记录后构建。
