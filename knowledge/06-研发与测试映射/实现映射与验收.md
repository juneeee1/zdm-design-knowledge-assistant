# 实现映射与验收

## 目的
让设计知识能落到具体组件、接口与测试证据，避免“编号相同”被误读为“实现相同”。

## 当前边界
扫描快照中 designId 与 engineeringId 按一一对应约定填写。未读取业务代码或接口，不能称为完成 Code Connect、接口验证或自动化 UI 验收。486 条关系来自设计证据，非线上调用日志。

## 映射记录契约（建议）
| 字段 | 含义 | 当前未知时 |
| --- | --- | --- |
| designId | 设计类型编号 | 不得自造 |
| engineeringId | 研发类型编号 | 按约定记录，标记未核验 |
| platform / version | 适用端和实现版本 | 留空并提问 |
| componentPath / commit | 代码位置与可复现提交 | 留空 |
| fieldContract | 必填、可选、默认与空值策略 | 待接口样例 |
| stateMapping | 业务条件对应设计状态 | 不从变体名猜 |
| evidence / reviewer | 核验记录和负责人 | 待认领 |

## 建议验收流程
1. 先明确目标页面、端、版本与卡片编号，引用具体档案。
2. 用业务提供的脱敏样例覆盖常规、极限、缺失与失败条件。
3. 分别记录视觉差异、交互差异和字段差异，不用一个“还原度”总分遮盖。
4. 设计确认视觉目标；研发确认实现；涉及业务含义由产品裁决。
5. 形成带截图/代码/日期的结论，再更新人工确认状态。

## 样板用例
| 用例 | 输入 | 预期评审点 |
| --- | --- | --- |
| T01 | 长标题、长英文 | 不与价格和操作重叠，截断规则可追溯 |
| T02 | 缺图、缺价 | 使用确认过的兜底，不能造数 |
| T03 | 多标签与多优惠条件 | 组合优先级明确 |
| T04 | 重复点击与失败 | 不伪造成功、不丢输入 |
| T05 | 深色/大字号 | 仅在目标端声明支持后验收 |
| T06 | 广告视频比例冲突 | 按确认后的素材集合验收 |
这是一份评审用例草案，未运行实际产品测试。
