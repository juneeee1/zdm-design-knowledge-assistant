# 组件选型与编号边界

## 一句话用途
为选卡片、比较卡片、生成页面建立统一的查询路径。

## 标准预览与来源
卡片事实来自 source/card-finder，查询使用现有 zdm-card-knowledge 工具；本档案不复制全量卡片表。

## 适用与不适用
适用于已有卡片的查找与评审。不能以搜索排序证明适用性，不能把 PC 官网与 App 来源 Frame 自动连接。

## 选型步骤
1. 写明目标端、页面、用户任务、数据类型和目标版本。
2. 按编号或关键词检索候选，阅读用途线索及来源备注。
3. 检查页面关系的 evidenceLevel、humanReview 和 relationshipStatus；被拒绝的关系不作为推荐依据。
4. 检查变体与内容开关是否已经覆盖，不为同一类型的新状态造编号。
5. 用已有页面映射验证；没有业务语义或存在冲突时，输出候选与待确认问题。
6. 交付中记录选中编号、来源、状态、例外和版本。

## 容易混淆的边界
| 对象 | 表示什么 | 不表示什么 |
| --- | --- | --- |
| 编号 | 一种卡片类型 | 单张图片或某个状态 |
| 页面 | 业务页面 | 每一个原始 Frame |
| 场景 | 页面内的用户任务/上下文 | 页面所有异常状态 |
| 状态 | 条件触发后的变化 | 新业务类型 |
| Frame | 设计证据容器 | 已确认的完整页面定义 |

## 研发与测试
设计编号与研发编号按项目约定一一对应；真实组件路径和接口实现仍需研发核验。扫描中 status=confirmed 是旧字段，不能替代 humanReview.status=approved。

## 确认记录
编号治理来自用户项目约定；具体业务选型仍待确认。
